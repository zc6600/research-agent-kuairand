# Runner Contract

Runner adapters translate one non-interactive agent invocation into CLI-specific arguments. They do **not** define research method, scientific judgment, memory ownership, or State semantics. Those come from launcher prompts and the target-pinned `SYSTEM_CONTRACT.md` / `RESEARCH_METHOD.md`.

## Common workspace model

META and Scientist both run with the target project as their working directory. Role separation is semantic: launcher prompts, environment variables, and the project contract assign authority.

Per-run scratch lives under ignored runtime state:

```text
research_record/runtime/tmp/<run-id>/
```

Git is the State version store, not the research ledger. Runner adapters must not infer scientific progress or chronology from commit order.

## One runner interface

Every adapter implements one role-neutral `invoke()` operation. META and Scientist use the same runner transport; only role prompts and environment assignment differ. For non-interactive calls, the launcher sends the prompt through stdin rather than putting the injected context in `argv`; this keeps large context out of process listings and argument-size limits. Interactive Goal mode keeps its PTY input separate.

The optional reasoning-effort levels are `low`, `medium`, `high`, and `max`. Runner-specific flags express transport, model choice, native autonomy, or permission behavior; they must not create a different research-agent architecture for one runner.

## META launch

`step`, `run`, and `resume` each launch one META process. Before invoking the runner, the launcher injects the target files META must reconstruct at startup: `AGENTS.md`, `task.md`, `PERSONAL.md`, `SYSTEM_CONTRACT.md`, `RESEARCH_METHOD.md`, `RESEARCH_BRIEF.md`, `RESEARCH_RECORD.yaml`, `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, `KNOWLEDGE.md`, `RESEARCH_INTUITION.md`, `DO_BETTER.md`, and `STATE.yaml` when present. It also injects the target path, starting cycle id, delegated Scientist-cycle policy, and one final result path. `SKILL.md` is external-agent documentation and is not injected or read by the runtime agent. Actual implementation, evaluator, reports, logs, and deeper evidence remain available for inspection when needed.

The code-level file manifest is the launcher source of truth; it is deliberately
not generated by reading an external Skill file:

| Runtime role | Injected startup files |
| --- | --- |
| META | `AGENTS.md`, `task.md`, `PERSONAL.md`, `SYSTEM_CONTRACT.md`, `RESEARCH_METHOD.md`, `RESEARCH_BRIEF.md`, `RESEARCH_RECORD.yaml`, `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, `KNOWLEDGE.md`, `RESEARCH_INTUITION.md`, `DO_BETTER.md`, and `STATE.yaml` when present |
| Scientist | `AGENTS.md`, `task.md`, `PERSONAL.md`, `SYSTEM_CONTRACT.md`, `RESEARCH_METHOD.md`, `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, `KNOWLEDGE.md`, `RESEARCH_INTUITION.md`, `DO_BETTER.md`, the active coordination JSON, and `STATE.yaml` when present |
| Never injected as startup context | `SKILL.md`; Scientist also excludes META-owned `RESEARCH_BRIEF.md` |

For `run` and `resume`, the same META process may supervise multiple fresh Scientist sessions. It reads their persisted reports, audits actual evidence and implementation changes, maintains shared research memory, writes `STATE.yaml` when a retained Scientist implementation should become a State, and decides whether another fresh trajectory is worth the cost.

META does not choose the Scientist's hypothesis, experiment, model family, feature, objective, or research direction, and it does not edit the contents of `system/**`. When crystallizing a State it may stage and commit the retained Scientist-authored `system/**` exactly as left together with META's descriptor.

## Scientist launch

Scientist also runs with the target as working directory. Its bootstrap prompt directly injects the startup files in the code-level Scientist manifest: `AGENTS.md`, `task.md`, `PERSONAL.md`, `SYSTEM_CONTRACT.md`, `RESEARCH_METHOD.md`, `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, `KNOWLEDGE.md`, `RESEARCH_INTUITION.md`, `DO_BETTER.md`, the active Serial/Parallel coordination JSON, and `STATE.yaml` when present. `RESEARCH_BRIEF.md` and `SKILL.md` are intentionally not injected: the runtime contract excludes the former to avoid META's trajectory compression, and the latter is external-agent documentation. The prompt explicitly forbids reading any on-disk `SKILL.md`. The actual implementation, evaluator, and deeper history remain available for inspection when needed.

Normal Scientist cold start receives the compact maintained environment:

- `task.md`, `AGENTS.md`, and `PERSONAL.md`;
- `SYSTEM_CONTRACT.md` and `RESEARCH_METHOD.md`;
- `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, and `KNOWLEDGE.md`;
- `RESEARCH_INTUITION.md` and `DO_BETTER.md`;
- current `STATE.yaml` and `system/**`;
- active Serial or Parallel coordination input.

`RESEARCH_RECORD.yaml`, the State-linked Scientist report, other historical reports, raw logs, source, and evaluator behavior are deeper provenance to inspect when concise memory is insufficient or worth challenging. A fresh Scientist is cognitively fresh, not scientifically blank.

Scientist owns scientific judgment, experiment evidence/logs, its new append-only free-form report, and implementation changes under `system/**`. It may update the shared environment files `EXPLORE.md`, `OPTIMIZE.md`, `ENGINEERING.md`, and `KNOWLEDGE.md` during research. It does not edit `RESEARCH_RECORD.yaml`, `RESEARCH_BRIEF.md`, `RESEARCH_INTUITION.md`, `DO_BETTER.md`, or `STATE.yaml`, and does not create State tags.

At session end Scientist writes one free-form report under `research_record/reports/`. The runner does not parse, normalize, summarize, or validate report content. There is no report schema.

## State creation boundary

State creation is post-Scientist supervision:

```text
Scientist leaves system/** + evidence + Report
→ META audits them
→ META writes STATE.yaml with scientist_report provenance
→ META commits unchanged system/** + STATE.yaml
→ canonical State machinery creates state/<id>
```

`research-agent state create` requires the referenced Scientist report to exist. Historical State materialization returns that report path and rejects missing provenance.

## `launch-inner`

`launch-inner` starts exactly one fresh Serial Scientist after the runtime validates and injects the current coordination brief. It does not create an outer META process, claim a cycle slot, maintain a launch counter, or interpret scientific progress. An already-running Scientist may not recursively call it.

## Permissions

Automated research paths require explicit edit permission. Runner-specific permission flags are transport details and do not change role ownership. Broad technical filesystem access does not grant semantic authority to edit an artifact owned by another role.

## Parallel

Parallel uses isolated worktrees and the same Scientist ownership contract. Reports remain free-form and are snapshotted as provenance. A Parallel Scientist may change `system/**` but must not manufacture `STATE.yaml` merely from branch coordination metadata.

The legacy Parallel promotion runtime still has separate mechanics around implementation adoption. It must not be treated as an alternative ownership model; any selected implementation can become a canonical State only after META-style post-session supervision has produced the descriptor from the selected report and evidence.

## Version checks and failures

The current project record format is `research-agent-record-v5`; incompatible project-local records are rejected rather than silently mixing old prompts and new runtime semantics.

Missing injected startup files, empty injected files, missing executables, unsupported command shapes, and non-zero META or Scientist runner exits fail visibly. `STATE.yaml` is optional because a project without a State is a valid initial condition. Runtime logs and coordination JSON are operational state, not scientific evidence or a second research ledger.
